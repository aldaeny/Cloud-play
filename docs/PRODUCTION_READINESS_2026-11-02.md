# Cloud Play Iraq — تدقيق وتنفيذ مرحلي، 2 نوفمبر 2026

## النتيجة
**غير جاهز للإطلاق التجاري أو العام كمنصة بث متكاملة.** الموقع الحالي عام ويقدم فيلمين قصيرين من Blender بترخيص مذكور وإسناد، لكنه ليس backend إنتاجياً أو نظام حسابات أو منصة مسلسلات وقنوات فعلية. لا يعني نجاح بناء الواجهة أو اختبارات الوحدة جاهزية أمنية أو حقوقية.

## 1. التدقيق وما كان موجوداً
- Next.js Pages Router للويب على Vercel ومصدر عام مرتبط بـGitHub؛ الموقع كان يستجيب 200. Next.js للوحة إدارة منفصلة وغير منشورة، وNestJS/Prisma/PostgreSQL لخلفية غير منشورة، وملفات worker/Redis/FFmpeg وواجهات محمولة جزئية.
- الويب يتضمن RTL/English وثيمين ومقدمة وأصول علامة ومشغلاً، فيلمين بترخيص وإسناد، وIPTV/XMLTV اختيارياً لا يعمل دون مصادر وإقرارات حقوق. Firebase وiptv-org وXtream القديمة مغلقة بسياسة عدم الثقة.
- قاعدة Prisma ومigrations ونماذج عنوان/مسلسل/حلقات/حقوق ومستخدم/أدوار موجودة؛ لا يوجد مشروع Supabase مرتبط بقاعدة إنتاج، ولا توجد قاعدة نشر أو بيانات حقيقية مؤكدة في هذا التقييم.
- لوحة الإدارة المتاحة في المصدر دخول وعرض عناوين فقط، وليست لوحة إدارة شاملة. حراس الصلاحيات موجودون في API، لكن لا يجوز اعتبار نشر إداري آمناً أو جاهزاً حتى اختبارات قاعدة فعلية وحقوق واختبار شامل.

## 2. بنية مستهدفة دون استبدال غير ضروري
- واجهة Next.js الحالية، ومشغل HTML5 مع HLS Native أو hls.js عند الحاجة. البيانات الوصفية منفصلة عن ترخيص الفيديو.
- NestJS/Prisma مع Postgres مدارة بعد إعدادها بأمان، API خلف HTTPS، حسابات وصلاحيات وتدقيق مركزي. تخزين الاعتمادات على الخادم فقط، ولا proxy مفتوح. تسجيل خروج حقيقي وتدوير/إبطال refresh وقيود rate limit مشتركة بين النسخ مطلوبة قبل ربط الحسابات.
- دليل قنوات وXMLTV بمصدر مشغّل مرخّص ومنفصل، مع حساب تكلفة نقل الفيديو وتخزينه مسبقاً، والتحقق من CORS والترخيص والمناطق ومدة الصلاحية. دعم Xtream آمن يحتاج تصميم جلسة/بث مصرح، ولا يكفي إخفاء بياناته في الواجهة.
- يتم التعامل مع TMDB كمصدر بيانات وصفية فقط بعد ترخيص الاستخدام المناسب وإعداد مفتاح الخادم والإسناد المطلوب. ليس مصدراً للبث. لم تُفعّل واجهته هنا.
- Next.js Admin على نطاق/خدمة مستقلة محمية، وAPI تفحص دور المدير وصلاحياته الخادمية. تُفعّل وظائف الكتابة تدريجياً بعد الاختبارات والسجل والمراجعة.

## 3. المنفذ بهذه المرحلة
- صفحات `/movies`, `/movies/bunny`, `/movies/sintel`, `/series`, `/live`, `/search`, `/favorites`, `/continue`, `/settings`, `/login` مع العربية والإنجليزية، اختبارات تجاوب، وروابط تنقل. صفحة المسلسلات فارغة صراحةً، و`/login` توضح أن الحسابات غير متصلة وليست نموذج تسجيل وهمياً. إعدادات الحركة التفصيلية لا تزال ضمن الصفحة الرئيسية؛ صفحة الإعدادات الجديدة توفر اللغة والمظهر والرجوع للرئيسية. البحث والمفضلة والمتابعة تخص الأفلام المتاحة فقط، والمفضلة والتقدم محليان لا متزامنان.
- اختيار الجودة والصوت والترجمة في مسار hls.js عند توفر المسارات في القائمة. مسار Native يعتمد على قدرات أزرار المتصفح/النظام؛ ليس كل متصفح يعرض الخيارات نفسها. عناصر الفيديو الأصلية توفر التشغيل والصوت وملء الشاشة بحسب الجهاز. إعادة المحاولة متاحة؛ لا يوجد اختيار تلقائي لسيرفر بديل أو DRM.
- skeleton لتحميل القنوات، حالات غياب، `robots.txt`, sitemap, metadata canonical، وnoindex للصفحات الشخصية/البحث. لا تُمثّل معلومات TMDB أو مسلسلات تجريبية بيانات حقيقية.
- Backend في المصدر: إزالة سر JWT الافتراضي، رفض مفاتيح وصول/تحديث غائبة أو متطابقة، رفض تسجيل دخول/تحديث المستخدم غير النشط، وتقييد خوارزمية التحقق. تحقق أولي عند تشغيل API في production من المفاتيح المنفصلة وقاعدة البيانات ومعرّف tenant. محدد معدل محدود الذاكرة وأشد للحسابات، لكنه **محلي لكل عملية فقط** ويتطلب حلاً مشتركاً وإعداداً موثوقاً للبروكسي في الإنتاج؛ الافتراضي لا يثق برؤوس توجيه يرسلها العميل.
- المقدمة والشعارات لم تُعدّل.

## 4. الاختبارات المنفذة والحدود
- Web/Admin: lint وbuild وTypeScript ضمن Next build: PASS؛ الويب به 3 تحذيرات صور سابقة، وNext 16 يحذّر من تقادم دعم React 18.
- API: lint/build و16 مجموعة/72 اختبار وحدة: PASS، ومنها حالات مفاتيح JWT، المستخدم غير النشط، وضبط production، وحدود المعدل. هذه ليست اختبارات تسجيل دخول بقاعدة بيانات فعلية أو اختبارات اختراق.
- Chromium محلي: كل الصفحات الجديدة بعروض 320/390/768/1440، بحث، مفضلة، تفاصيل، لغة واتجاه، وحالة حساب غير متصل: PASS.
- HLS اصطناعي محلي: مقاطع مولّدة محلياً مع جودتين ومساري صوت وترجمة. شُغّل hls.js في Chromium واختُبرت عناصر الاختيار؛ الأمر `FFMPEG=/path/to/ffmpeg scripts/player-hls-fixture-test.sh` يعيد الاختبار ويحذف الملفات الاصطناعية عند الانتهاء. لا يثبت الاختبار فعلياً أجهزة iOS/Safari/TV أو جميع قوائم الموفرين.
- اختبارات M3U/XMLTV ومصدر Xtream القديم المغلق: PASS على بيانات اصطناعية. بيانات حقيقية وحقوق مزوّد وDRM وفشل الشبكة عبر جميع المتصفحات لم تُختبر.
- محاولة اختباري admin-proxy وeditorial-security في هذه الجولة لم تُنفذ لغياب إعدادات `DATABASE_URL` و`JWT_ACCESS_SECRET`. لا تُحسب نجاحاً لهذه الجولة. لم تُجر اختبارات جهاز أصلي أو بيانات إنتاج.

## 5. التكلفة والحقوق
- لا توجد خدمة مدفوعة جديدة فُعّلت في هذه المرحلة. Vercel Hobby حالياً مجاني ضمن الحصة لكنه مخصص للاستخدام الشخصي غير التجاري، لذا لا تفترض أهليته لإطلاق تجاري: https://vercel.com/docs/plans/hobby
- Supabase Free: $0 وحدود موارد وتوقف بعد أسبوع خمول؛ خطة Pro تبدأ من $25 شهرياً وتتجاوز سقف $15 قبل تكلفة بث أو إضافات: https://supabase.com/pricing
- Render يذكر compute مدفوعاً من $7 شهرياً لبعض الموارد، لكن التجميعة والضرائب والتخزين والنقل قد تتجاوز الميزانية: https://render.com/pricing . لا يوجد تقدير موثوق لمنصة بث فعلية حتى معرفة الجمهور وجودة ومدة الفيديو ونموذج التوزيع والترخيص.
- TMDB مجاني لغير التجاري مع الإسناد المطلوب، ويحتاج ترخيصاً تجارياً للاستخدام التجاري: https://developer.themoviedb.org/docs/faq . لا تُرسل مفاتيح أو بيانات اعتماد في المستودع العام.

## 6. متطلبات الإطلاق الحقيقية
1. توفير قوائم وعقود IPTV وEPG وحقوق كل قناة/منطقة؛ اختبارات مزوّد فعلية من العراق. الاعتمادات فقط على خادم آمن، لا في الواجهة أو Git.
2. إعداد قاعدة PostgreSQL وخادم API ونسخ احتياطية وسجل وتقييد معدل موزع بعد التحقق من الخطة والحصة. تنفيذ إبطال الجلسات، منع سرقة refresh، وسياسات الحسابات والتدقيق، واختبارات فعلية متكاملة قبل نشر تسجيل الدخول.
3. بناء إدارة كتابة كاملة بترخيص/صلاحيات وتدقيق لكل عملية؛ ربط المسلسلات والمواسم والأفلام الحقيقية وفق الحقوق والتوفر.
4. إعداد TMDB مرخص وإسناده ومفتاح خادم إن كان استخدامه مناسباً؛ البيانات الوصفية لا تمنح حقوق بث.
5. اختيار خطة استضافة تتوافق مع الاستخدام التجاري والميزانية. الحاجة إلى ميزانية أعلى أو موافقة على مزود بديل احتمال حقيقي، خصوصاً مع نقل الفيديو.
6. اختبارات Safari/iOS/Android/Smart TV، الأمان والاستعادة والأداء وDNS وCORS، وبث المصادر الحقيقية؛ لا يُدّعى اجتيازها قبل تنفيذها.
