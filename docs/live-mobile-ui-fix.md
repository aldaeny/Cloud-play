# إصلاح واجهة التلفزيون على الجوال — Cloud Play Iraq

تاريخ التنفيذ: 2026-11-08 · الفرع: `arena/99940171-cloud-play` · الأساس: `main` بعد دمج PR #17

## 1. الملخص

تم إصلاح تخطيط صفحة `/live` والشريط السفلي المشترك **دون إعادة بناء المشروع ودون تغيير الهوية البصرية**
(الشعار، الألوان، الخطوط، أشكال الأزرار، موضع أزرار الشريط، الزر المركزي المرتفع وتأثيره كما هي).
التغييرات محصورة في **ملفي CSS** + إعادة تسمية أصناف في ملفي صفحة Live لتفادي تصادم مع أنماط الصفحة الرئيسية،
بالإضافة إلى ملف اختبار جديد وصور التوثيق.

## 2. ما تم فحصه قبل التعديل

- `apps/web/src/styles/{live,global-nav,globals,app-shell,motion}.css`
- `apps/web/src/components/nav/GlobalNav.tsx` و`src/lib/nav-routes.ts`
- `apps/web/src/components/navigation/AppShell.tsx` و`apps/web/app/live/page.tsx` و`app/live/[id]/page.tsx`
- `apps/web/src/components/channels/ChannelCard.tsx` (مرشّحات التصنيف/الدولة/الجودة/الترتيب)
- قياسات فعلية في Chromium قبل التعديل على المقاسات 375/390/430/820/1440 مع RTL/LTR وداكن/فاتح.

## 3. الأسباب الجذرية (مثبتة بالقياس، لا بالتخمين)

| # | المشكلة | السبب الجذري | القياس قبل الإصلاح |
|---|---------|--------------|---------------------|
| 1 | تسميات الشريط السفلي مقصوصة أفقياً (نصف الحرف) | `.cp-nav-btn` كان يحتاج 64px داخل شريط 62px، فقلّص flex صندوق التسمية إلى 6px مع `overflow:hidden` | `clientHeight=6px` مقابل `scrollHeight=12px` |
| 2 | زر «إعدادات الحساب» يقع تحت الشريط عند فتح الصفحة | ارتفاع بطاقة الحالة الفراغية 255px + مسافات رأسية زائدة (28/22/14) دفعت الزر إلى y≈757 بينما أعلى الشريط 747 | تداخل ≈ 10px عند أول ظهور |
| 3 | قصّ أول/آخر تصنيف وحلقة التركيز | حشوة الشريط `2px` فقط، أقل من `outline-offset:3px + 3px`، وبدون `scroll-padding` أو احتواء تمرير اللمس | حشوة 2px، لا `overscroll-behavior` |
| 4 | حقول الدولة/الجودة/الترتيب غير متساوية | `display:flex` مع `min-width:145px` يسبّب التفافاً غير منتظم حسب العرض | عروض متفاوتة حسب المقاس |
| 5 | الملاحظة الأخيرة والرابط ملتصقان | لا توجد مسافة بين `.live-note` والرابط الذي يليه | `margin = 0` |
| 6 | تصادم أصناف مع الصفحة الرئيسية | `globals.css` يعرّف `.live-section{padding-bottom:85px}` و`.live-panel{display:flex;min-height:214px;overflow:hidden}` وهي نفس الأسماء المستخدمة في Live | ترث أقسام Live حشوة 85px، ولوحات التفاصيل تتحول إلى صف flex |
| 7 | التركيز بلوحة المفاتيح قد يستقر تحت الشريط | لا يوجد `scroll-padding-bottom` على عنصر التمرير | `scroll-padding-bottom: 0` |

**ملاحظة مهمة عن المساحة السفلية:** الحاجز الموجود مسبقاً `body.cp-has-global-nav{padding-bottom:calc(120px + safe-area)}`
كان **صحيحاً** (ارتفاع الشريط المرئي فعلياً 97px + safe-area، أي فائض 23px). لذلك لم يُضف حاجز مكرر؛
أُضيف فقط `scroll-padding-bottom` المطابق له حتى لا يستقر التركيز/الروابط الداخلية تحت الشريط.

## 8. ملاحظات متبقية بصدق

1. **التمرير تحت الشريط سلوك مقصود:** الشريط عائم وثابت، لذا يمر المحتوى تحته أثناء التمرير.
   المطلوب والمُحقَّق هو ألا يبقى أي عنصر محجوباً بشكل دائم: عند نهاية التمرير يوجد خلوص ≥ 90px
   لكل زر/رابط/حقل، والتركيز بلوحة المفاتيح يستقر فوق الشريط.
2. **الحالة الفراغية باقية كما هي نصاً ووظيفة:** «لم تُربط قائمة قنوات مرخّصة بعد».
   لم تُضف قنوات وهمية أو روابط تجريبية؛ تظهر القنوات فقط بعد ربط مصدر مرخّص من المشغّل
   (`CLOUDPLAY_IPTV_RIGHTS_CONFIRMED=true` مع `CLOUDPLAY_IPTV_M3U` أو `CLOUDPLAY_IPTV_FILE`).
3. **الاختبار على Chromium فقط:** لم يُشغَّل Safari/iOS حقيقي في هذه البيئة؛ حساب `env(safe-area-inset-bottom)`
   مُتحقَّق منه عبر CSS والقياسات، لكن يُنصح بتأكيد بصري على iPhone حقيقي بعد النشر.
4. **5 تحذيرات ESLint سابقة** بخصوص `<img>` في مكوّنات غير متعلقة بهذه المهمة، لم تُعدَّل لتقليل نطاق التغيير.
